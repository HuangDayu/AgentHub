# AgentHub 产品路线图规划
> 日期：2025-06-10 · 状态：待审核 · 版本：v1.0

---

## 1. 产品愿景

**打造企业级 AI Agent 全生命周期管理的一站式基础设施平台**，让企业能够：
- **快速构建** — 零代码/低代码创建 AI Agent
- **安全运行** — 多租户隔离、审计溯源、权限管控
- **持续进化** — Agent 自我学习、团队协作、知识积累
- **无缝集成** — 连接企业现有系统（数据库、API、消息队列）

| 问题 | 严重度 | 影响 |
|------|--------|------|
| 测试覆盖不均 | 高 | Controller 集成测试 40 个覆盖率高，但 UseCase 层几乎无单元测试 |

### 阶段二：Agent 智能升级（2025 Q4）🧠

**目标**：让 Agent 从"工具执行者"变成"智能协作者"

| 序号 | 功能 | 优先级 | 工作量 | 依赖 |
|------|------|--------|--------|------|
| P2.1 | **长期记忆持久化** | P0 | 5 人天 | 无 |
| P2.2 | **Agent 自我进化** | P0 | 10 人天 | P2.1 |
| P2.3 | **多模态 Agent（图/音/视频）** | P1 | 8 人天 | 无 |
| P2.4 | **Graph RAG** | P1 | 8 人天 | 现有 RAG |
| P2.5 | **Agent 调试器（Debugger）** | P1 | 5 人天 | 现有 Trace |
| P2.6 | **Agent 协作协议** | P2 | 10 人天 | P2.2 |

**核心功能描述**：

#### P2.1 长期记忆持久化
- Agent 将历史对话和决策关键信息存入向量数据库
- 支持记忆类型：事实记忆、过程记忆、偏好记忆
- 记忆自动摘要 + 按相关性检索
- API：`GET /workspaces/{wsId}/agents/{id}/memories?query=xxx`

#### P2.2 Agent 自我进化
- Agent 在每次任务完成后自动复盘（self-reflection）
- 提取成功/失败模式，存入"经验库"
- 下次相似任务自动调取经验指导决策
- 架构：Memory → Reflection → Pattern Extraction → Behavior Tuning

#### P2.4 Graph RAG
- 在文档实体间构建知识图谱（实体 + 关系）
- 检索时走：向量相似度 → 图遍历 → 融合排序
- 适合多跳推理问题（"谁的客户投诉了产品X？"）

### 阶段三：企业级能力深化（2026 Q1）🏢

**目标**：满足大型企业合规、安全、管理需求

| 序号 | 功能 | 优先级 | 工作量 | 依赖 |
|------|------|--------|--------|------|
| P3.1 | **SSO/OIDC/LDAP 集成** | P0 | 5 人天 | 无 |
| P3.2 | **RBAC/ABAC 细粒度权限** | P0 | 8 人天 | 现有权限 |
| P3.3 | **用量计量与计费** | P1 | 5 人天 | P3.2 |
| P3.4 | **消息队列事件总线** | P1 | 5 人天 | 无 |

| P3.6 | **合约测试集成到 CI** | P2 | 3 人天 | P1.6 |

#### P3.1 SSO/OIDC 集成方案
- 支持 OAuth2 / OIDC 标准协议
- 集成 Spring Security OAuth2 Client
- 支持 Azure AD / Okta / Keycloak 等 IdP
- 兼容现有 JWT 令牌体系

#### P3.4 事件总线
- 基于 Redis Pub/Sub 或 Kafka
- 标准化领域事件（Agent 状态变更、任务完成、告警触发）
- 解耦微服务（为未来微服务化做准备）
- 事件 Schema 注册 + 消费者自动发现

## 4. 优先级评估矩阵

```
                   高风险
                    │
                    │ P3.1 SSO      P2.2 自我进化
                    │ P1.1 API 文档  P2.1 长期记忆
                    │ P1.2 单元测试   P4.1 插件 SDK
                    │
         低价值 ────┼──── 高价值
                    │
                    │ P2.3 多模态    P4.3 公开市场
                    │ P4.5 i18n     P1.5 前端测试
                    │ P1.6 契约测试  P3.4 事件总线
                    │
                   低风险
```

**策略**：先做左上象限（高风险+高价值），快速消除技术债务；再做右下（低风险+高价值），稳步交付功能。

## 6. 风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|----------|
| 单模块 Gradle 编译慢阻碍开发 | 中 | 高 | 阶段一即启用 Gradle 并行编译 + 构建缓存 |
| Agent 自我进化导致不可控行为 | 低 | 高 | 进化策略需人工审核 + 沙箱回滚机制 |
| 企业客户 SSO 集成复杂度超预期 | 中 | 中 | 先支持 Keycloak（最通用），再扩展商业 IdP |
| 插件 SDK 安全漏洞 | 低 | 极高 | ClassLoader 隔离 + SecurityManager + 代码签名 |

---

## 7. 总结

AgentHub 已具备业界领先的架构质量和功能广度。**接下来的核心任务是从"能跑"到"好用"到"好卖"**：

1. 先**消除技术债务**（测试、文档、一致性）→ 提升开发者信心
2. 再**增强智能能力**（记忆、进化、调试）→ 提升产品壁垒
3. 然后**满足企业合规**（SSO、权限、计量）→ 打开企业市场
4. 最后**开放生态**（SDK、市场、Webhook）→ 建立网络效应

> **一句话路线**: Q3 修内功，Q4 强智能，Q1 进企业，Q2 建生态。
